**Read the plan. Explore the maybes. Discuss an idea. Publish it when ready.**

You can browse this site without an account. These instructions describe the current working version; new pages or changes appear online only after a successful publication.

## Start here

1. Open [All guides](index.md) for the topics and navigation.
2. Read [the itinerary](itinerary.md) for the public summary of the adopted route and commitments.
3. Open [the daily travel guide](daily-travel-guide.md) to see the current plan with nearby possibilities beneath each day.
4. Follow a suggestion's **Research** link for the full description, sources, research date and unresolved questions.
5. Use the site's search to find a place or interest, such as Athlone, pottery or folklore.

The daily guide is a shortlist, not the whole inventory. Browse the topic pages for more choices: [activities and food](activities-and-food.md), [cheap eats](cheap-eats.md), [farms](farms-and-rural-industries.md), [folklore](folklore-and-ancient-sites.md), [ruins](ruins-and-abbeys.md), [riding](horse-riding.md), [makers](independent-makers.md), and [art, culture and music](art-culture-and-music.md).

## Our plan, our amendments and the debating floor

| Part of the system | What it means |
|---|---|
| **Wanderlog: the Constitution** | The adopted where, when and what. The itinerary here is a public summary, not a separately edited replacement. |
| **The wiki: unadopted amendments** | Maybes for weather, closures, energy, spare time or a deliberate change. |
| **Giscus and Hypothesis: the debating floor** | Places to discuss, introduce or revise those maybes. |

A popular comment, an approved wiki edit or a booking does not by itself update Wanderlog. A selected change stays pending until the authoritative plan reflects it. Existing uncertainties stay visible even in the adopted plan.

## Discuss a whole idea with Giscus

At the bottom of a guide, find **Read together** and the general discussion area. Sign in with GitHub when prompted to add a comment, reply or reaction. Reading the guide needs no sign-in.

Use this for a new suggestion, a question about the day, or discussion of which alternatives are appealing. Include a source link when correcting hours, prices or access.

For example: “Could we keep this gallery as the rainy-day alternative? Here is its current opening information.”

A comment starts a discussion. It does not immediately edit the guide or change the trip.

## Annotate a particular passage with Hypothesis

1. Select **Annotate this guide** in the guide tools or the **Read together** section.
2. The page reloads with the annotation sidebar open.
3. Select the relevant text and choose **Annotate**.
4. Sign in to Hypothesis to save your annotation, and check its sharing setting before posting.

Use this when the exact sentence matters: an access description, a price, a proposed date or an unclear claim. A Hypothesis account is separate from GitHub. Hypothesis annotations and Giscus discussions are separate conversations; one does not automatically copy into the other.

Keep personal contact information and private travel or reservation details out of public comments, edits and annotations.

## Propose a direct text change

**Edit this guide**, below the article, opens the Markdown source on GitHub. Sign in and use GitHub's branch/fork and pull-request process to propose the edit. A pull request is a proposed change, not a published page; review and merge come first.

For the generated daily guide, revise the underlying topic source or ask in chat to update its dated suggestion. Direct changes to the generated page are replaced on the next build.

Prefer discussion or an annotation if you are unsure how the wording should change. Bring the discussion link or quoted passage into a project chat when you want it considered for a wiki revision. Retrieval depends on available access; there is no automatic comment monitor.

## What can I ask in a project chat?

These are ordinary requests, not special commands. Use a chat opened in the Ireland project so its local files and workflow are available. The browser alone does not run these requests.

| What you want | Example request | What happens |
|---|---|---|
| Discover alternatives | “Find rainy-day options near Athlone without changing the planned route. Propose them first.” | Researchers check existing ideas and look for additional options; no public edit is approved yet. |
| Add approved research | “Write this finding to the public cheap-eats guide and queue it. Keep it a maybe.” | The public-safe edit is made, checked and staged locally. |
| Approve a researcher's edit | “Yes, add those two suggestions to the wiki and queue them.” | The approved changes enter the same local queue. |
| Keep a note private | “Record this preference privately; don't add it to the website.” | It stays in local planning records. |
| Use the debating floor | “Review these comments and propose a revised amendment. Don't publish yet.” | The editor preserves attribution, investigates claims and proposes revisions. Supply links or quotes if needed. |
| Record interest | “Record Monica's interest privately. This is not a booking or a change to Wanderlog.” | Interest is recorded separately from approval and adoption. |
| Check new events | “Reconcile the latest weekly events report with our current itinerary; show new options first.” | Dated reports are checked against the current route; they do not automatically change it. |
| Refresh the guide | “Refresh the daily guide from the current public itinerary and approved wiki sources, then queue the update.” | The reading copy and source links are rebuilt; research does not rewrite the baseline. |
| Inspect the queue | “Show me what is queued and what is already live.” | You get the local/publishing status before choosing the next step. |
| Save a local batch | “Commit the batch locally.” | Checks run and a local content commit is made; nothing is pushed or merged. |
| Share for review | “Commit and push the batch.” | The matching pull request is created or updated; it is not merged by this phrase alone. |
| Publish | “Publish the batch.” | The approved batch goes through checks, the matching PR, merge and deployment verification, subject to repository requirements. |

The default for an approved public guide edit is **queue it**, not deploy every save. You can accumulate edits over several chats. Research discoveries, comments and private-file edits do not automatically authorize public publication.

## How an edit reaches the website

**Approved edit → local queue → local commit → pushed pull request → checked merge → successful deployment.**

| Status | Is the public website updated? |
|---|---|
| Queued / staged | No. The selected changes are on the local computer. |
| Committed locally | No. They are saved in local Git history, not uploaded yet. |
| Pushed / pull request open | No. They are on GitHub for review. In this public repository, the pushed branch and PR are publicly readable even before the website changes. |
| Merged into main | Publication has been triggered, but deployment still has to finish. |
| Deployment succeeded | Yes. Reload the affected public page to read the new version. |

Substantive guide changes receive a schedule/route review and an independent guide review. Publication also checks sources, privacy, generated pages and links. If a check or required review blocks release, the status should say so; “pushed” must not be reported as “live.”

## Common questions

**I approved an idea. Why hasn't the site changed?** An approved public edit is normally queued for a batch. Ask to see the queue or to publish it. Approval to write privately has no public effect.

**I published an amendment. Is it now on our itinerary?** No. Publication changes the wiki. Adoption into Wanderlog is a separate action.

**I added a comment. Why isn't it in the guide?** Comments and annotations are discussion input. Ask in the project chat to review the thread, or supply a link and the relevant text.

**Why isn't every topic entry beneath a day?** The daily guide is curated. Ask to include an approved suggestion under suitable dates; the detailed inventory remains in the topic guides.

**Will weekly event searches rewrite the guide automatically?** No. The existing reports are inputs to a relevant refresh, not an automatic file feed or permission to change the trip.

**The comment or annotation tool is missing.** Reload the page and check whether a content blocker is preventing the embedded tool. Giscus discussions can also be found in the [repository's Discussions](https://github.com/robinsoncptdit/ireland-november-26/discussions). Mention the page and what failed in chat; don't assume a failed save was posted.

**I see an older page after publishing.** First confirm deployment succeeded for the intended batch. Then reload the production page. A local preview, an open PR and the live site can show different versions.
